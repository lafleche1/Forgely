# Référence Dofocus — plan d’implémentation

Objectif : faire de Dofocus la référence des conseils actifs de Forgely, avec des relevés du simulateur séparés des observations DOFUS.

Architecture : module Python de règles et relevés versionnés ; tous les conseils actifs passent par le même moteur. Une probabilité Dofocus ne s'applique que si l'objet, toutes les lignes et le reliquat correspondent exactement au relevé. Aucun apprentissage sur les résultats synthétiques.

Décision : exécution autonome autorisée par l'utilisateur ; conserver la pile Python/Tk et la branche de travail existante. Les règles non publiées ou non vérifiées ne seront pas inventées. Une collecte de quelques états ne couvre pas les combinaisons de tous les jets possibles.

- [x] Relever plusieurs familles d'équipements et les contraintes visibles, sans prix ni historiques économiques.
- [x] Écrire des tests : correspondance complète/jet différent/puits différent/exo/ligne interdite, absence de l'ancien taux Huz dans les conseils actifs, cohérence des conseils du tableau et de la fenêtre détaillée.
- [x] Vérifier RED ; implémenter règles, provenance, import hors ligne et moteur commun ; vérifier GREEN.
- [ ] Documenter couverture et limites ; vérifier la suite complète et le conditionnement Windows.
- [ ] Revue indépendante puis publication GitHub autorisée.

Critères : aucune donnée simulée dans la base d'observations ; aucun taux extrapolé ; aucun jet théorique inséré dans le jet OCR ; les poids s'appliquent aux caractéristiques compatibles de tous les objets, les probabilités restent contextualisées.

## Vérification et revue

- Base avant modification : 311 tests réussis, 14 ignorés.
- Première intégration : 323 tests réussis, 15 ignorés (9 GUI et 6 captures manquantes), 19 sous-tests.
- Les 322 cas transcrits ont la même empreinte FNV-1a que les relevés structurés du navigateur : 2593590883.
- Revue indépendante : deux problèmes de validation (structure et attribution/provenance) et un risque de fenêtre hors écran. Tests de reproduction RED puis corrections GREEN ; fenêtre de détail défilante et dimensions adaptées à l'écran.
- Décision : conserver la limite globale conservatrice 101 comme politique Forgely explicitement identifiée ; une impossibilité du jeu n'est pas déduite de cette garde.
- Décision : couverture chiffrée limitée aux états relevés ; pas de reconstruction supposée exacte d'une formule non publiée.

## Intégration concurrente

Main a évolué de bf77d46 à f281f311 pendant l'implémentation. Les deux modes, les dépenses de session et les corrections des contraintes ont été récupérés puis intégrés, sans écraser ces changements.
